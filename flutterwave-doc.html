🔁 General payment flow

Full control over the customer, payment method, and charge on your server.

① Create customer

Collect email, name, phone, address. Only email is required.

POST /customers { "address": { "city": "Gotham", "country": "US", ... }, "name": { "first": "King", "last": "James" }, "email": "james@example.com" }

② Create payment method

Card, mobile money, OPay, USSD, etc. Returns payment_method_id

POST /payment-methods { "type": "card", "card": { "nonce": "...", "encrypted_card_number": "..." } }

③ Initiate charge

Use customer_id + payment_method_id + amount, currency, reference.

POST /charges { "reference": "cedfa85a...", "currency": "USD", "customer_id": "cus_...", "payment_method_id": "pmd_...", "amount": 1234.56 }

④ Authorize

Handle next_action (pin, otp, redirect, additional fields, instructions).

⑤ Verify

Use webhook or GET /charges/{id} to confirm status: succeeded.

🔐 Security: Encrypt sensitive card data with nonce & encryption before sending.

⚡ Orchestrator flow

Simplified all‑in‑one charge — create customer & payment method in a single request.

Direct charge endpoint

POST /orchestration/direct-charges { "amount": 1234.56, "currency": "USD", "reference": "YOUR_REF", "payment_method": { "type": "card", "card": { ... } }, "customer": { "email": "...", "name": { ... }, "phone": { ... } } }
Supports card, mobile money, OPay, USSD, bank transfer.

Next actions & verification

Same next_action types as general flow. Verify via webhook or GET /charges/{id}.

💳 Card payments

Accept Visa, Mastercard, Amex, Verve, Afrigo.

Steps

  • Create customer (email required)
  • Create card payment method (encrypted details + nonce)
  • Initiate charge with customer_id & payment_method_id
  • Authorize: handle 3DS, AVS, PIN, OTP or redirect
  • Verify via webhook or GET charge
Recurring payments — use recurring: true with stored payment_method_id.

Auth models

  • 3DS / VBVSECURECODE — redirect to bank
  • External 3DS — your own verification provider
  • AVS — address verification (US/CA)
  • PIN — encrypted PIN + optional OTP
PUT /charges/{id} { "authorization": { "type": "pin", "pin": { "nonce": "...", "encrypted_pin": "..." } } }
Test with X-Scenario-Key: scenario:auth_3ds&issuer:approved
💡 Credential‑on‑File (COF) available on request

📱 Mobile money

M‑Pesa, MTN, Airtel, Orange, Wave · push notification or redirect.

Flow

  • Create customer (email + phone)
  • Create mobile_money payment method with country_code, network, phone_number
  • Initiate charge (currency must match country)
  • Customer authorises via push or redirect
  • Verify webhook / GET charge

🏦 Pay with bank transfer (virtual accounts)

NGN & GHS · dynamic (per‑transaction) or static (reusable) accounts.

Static account

  • Set amount: 0, account_type: "static"
  • Requires bvn or nin for NGN
  • Reusable for 1000 years

Dynamic account

  • Set expiry (seconds), account_type: "dynamic"
  • One‑time use, expires after set time

Create & verify

POST /virtual-accounts { "reference": "...", "customer_id": "cus_...", "amount": 1500, "currency": "NGN", "account_type": "dynamic", "expiry": 3600, "bank_code": "090567" }
Webhook charge.completed — verify status: succeeded and amount.
Test with X-Scenario-Key: issuer:approved or issuer:failed

📞 USSD payments

Offline, internet‑free · NGN only.

Flow

  • Create customer
  • Get bank list (GET /banks?country=NG)
  • Create USSD payment method with account_bank
  • Initiate charge → next_action.payment_instruction with USSD string
  • Customer dials, enters PIN
  • Verify webhook / GET charge
Example next_action
"note": "Please dial *1414# to complete this transaction"
No extra test configuration needed — use sandbox credentials.

⚡ OPay payments

NGN only · redirect to OPay for authorisation.
  • Create customer
  • Create opay payment method (no extra fields)
  • Initiate charge → next_action.redirect_url
  • Customer logs into OPay and authorises
  • Verify via webhook or GET charge
POST /payment-methods { "type": "opay" }

✅ Verification & testing

Webhooks

Configure in dashboard. Listen for charge.completed events. Always verify:

  • status = succeeded
  • amount matches expected
  • customer.id matches user
  • reference consistent
Sample webhook payload { "type": "charge.completed", "data": { "status": "succeeded", "amount": 200, "currency": "NGN", ... } }

Manual verification

GET /charges/{id} with your access token.
